Part 1 prints `hello world` on UART0 after the existing boot-info checks. The design notes, including how to test it in the course image, are in `homeworks/hw1/part1.md`.

`minemu_kernel_main` still rejects a bad `minemu_boot_info` and fail-stops without printing. On the success path it emits trace event `1`, then `minemu_printf("hello world\n")`, then spins in `minemu_fail_stop`.

The send path is split into two layers:

- `kernel/src/runtime/uart.c` is a polled driver. Each access is a 32-bit operation on `struct minemu_uart_regs`. Transmit waits for `TX_READY`, then writes the byte with the high bits clear, which is what the device ABI requires for `TX_DATA`. `minemu_uart_getc` is a non-blocking poll for part 2.
- `kernel/src/runtime/console.c` binds that driver to UART0 and provides `minemu_printf`. The hello-world string uses the plain-text path. `%c`, `%s`, `%d`, `%u`, `%x`, `%X`, and `%p` are there for later logging.

Both objects are linked from `kernel/Makefile`.
